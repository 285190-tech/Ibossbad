# Security finding follow-up

- Message receivers check sender origin and the expected frame window. The GUST WISP bridge also binds the tab ID to its current blob frame and isolates WebSocket IDs by tab. The extension execution bridge only accepts messages from the explicitly opened extension popup. Installed extensions and proxied pages must still be considered untrusted: proxied HTML can execute in the application origin today. Sender checks are not a substitute for isolating untrusted content on a separate origin. A secure isolation redesign is needed to protect application state and credentials from same-origin content.
- JavaScript URLs are refused by navigation. Explicitly installed extension popups and the developer tools still have code-execution functionality; installing an extension is a trust decision.
- The default Stream and self-hosted WISP paths already reject private/reserved IP destinations at connection time. `/api/check-url` now validates the URL and rejects non-public IP literals, in addition to checking configured domain rules. It is a preflight, not a DNS or network enforcement boundary: connection-time checks are necessary for DNS rebinding protection. External WISP relays are not subject to the server's IP or domain policy, and current self-hosted WISP streams do not enforce the admin domain lists. Do not rely on the preflight to enforce policy for every subresource or relay.
- Public status no longer exposes DNS cache counters or the client IP. The Supabase anon/publishable key and URL remain because browser-side login and cloud-sync fallback use them. An anon key is intended for public clients, not a secret; Supabase row-level security and auth policies must be configured correctly. Service-role keys must never be sent to clients. Removing the anon key requires redesigning those fallback flows.
- `nosniff` and a same-origin referrer policy apply to the app shell, UI assets, and API, not to rewritten remote content. The proposed `default-src 'self'; script-src 'self'` policy is not enabled: proxy/runtime components use blob and data URLs, WebAssembly, dynamic execution, inline styles/scripts, WebSockets, and Supabase. A strict policy needs a route-by-route redesign and real browser compatibility tests; do not interpret the added headers as complete CSP protection.
- Chat messages and poll fields are escaped in both text and HTML attribute contexts.
